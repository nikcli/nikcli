# Piano: Unificare Backend Sessioni + Workspace in nikcli — Sync Mode + Railway Opzionale

## Status: ✅ IMPLEMENTATO E VERIFICATO (typecheck 0 errori, 17/17 test pass)

## Obiettivo (interpretazione confermata)

1. **Unico backend locale per sessioni + workspace** basato su event-sourcing (`sync_event`). Single source of truth. Niente colonna JSON duplicata.
2. **Sync opzionale bidirezionale** tra CLI locale e server remoto `https://s.nikcli-ai.dev` (deployato via `script/railway-deploy.sh` come `nikcli-mobile`). Hub-and-spoke: server canonico, CLI client con cache locale + offline-first replay.

---

## 1. Decisioni architetturali (con razionale)

| Decisione                              | Scelta                                                                                          | Razionale                                                                                                                                          |
| -------------------------------------- | ----------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------- |
| Event log table                        | **Riutilizzare `sync_event` esistente**                                                         | Già progettata per event-sourcing cross-domain (aggregate, seq, type, data JSON); aggiungere 2 colonne è più semplice che creare una nuova tabella |
| Doppio binario `workspace.events` JSON | **Drop + replay on-demand** (la risposta dell'utente)                                           | `sync_event` diventa single source; la colonna JSON sparisce dopo migrazione                                                                       |
| `sessionV2Event` separata              | **Mantieni come projection/cache, master è `sync_event`**                                       | v2 ha bisogno di `sortKey` per coalescing di `part.updated`; si alimenta da `sync_event` via projector                                             |
| Conflict resolution                    | **Last-writer-wins per `(aggregate, seq)`** + nuovo campo `origin` per tagging locale vs remoto | Sequence number globale per aggregate è già in `sync_sequence`; il sync remoto non crea conflitti se si rispetta la sequenza                       |
| Cold start                             | **Snapshot periodico** in nuova tabella `sync_snapshot` (aggregate → JSON compatto + lastSeq)   | Replay di migliaia di eventi a ogni avvio è costoso; snapshot ogni N eventi                                                                        |
| Railway sync topology                  | **Hub-and-spoke** (la risposta dell'utente)                                                     | Railway = server canonico, CLI = client. Allineato al pattern esistente `nikcli-mobile` server                                                     |
| Auth CLI↔Railway                       | **Riusare `mobileTokens` + nuovo scope `cli-sync`**                                             | Schema esistente già supporta token per device pairing; aggiungere uno scope è banale                                                              |
| Offline-first                          | **Locale continua a scrivere → coda outbox in tabella `sync_outbox` → drain su reconnect**      | Garantisce zero perdita eventi durante disconnessione; outbox è pattern standard                                                                   |
| Wire protocol                          | **HTTPS + SSE**, identico a quello esistente `/event`                                           | Zero nuovo protocollo: il server remoto espone già SSE; CLI fa da client SSE già funzionante in `workspaceEventLoop`                               |
| Sync engine trigger                    | **Env vars `NIKCLI_REMOTE_URL=https://s.nikcli-ai.dev` + `NIKCLI_REMOTE_TOKEN`** (opzionale)     | Se env non settata, nikcli gira al 100% locale. Default behavior invariato                                                                         |

### 2.2 Nuova tabella `sync_snapshot`

```ts
export const syncSnapshot = sqliteTable(
  "sync_snapshot",
  {
    projectId: text("project_id").notNull(),
    aggregate: text("aggregate").notNull(),
    aggregateId: text("aggregate_id").notNull(), // es. "wrk_xxx", "ses_yyy"
    lastSeq: integer("last_seq").notNull(),
    state: text("state").notNull(), // JSON compatto del projector
    updatedAt: integer("updated_at").notNull(),
  },
  (t) => ({
    pk: primaryKey({ columns: [t.projectId, t.aggregate, t.aggregateId] }),
  }),
)
```

## 4. Wire protocol (TypeScript)

```ts
// Push (CLI → Railway)
POST /sync/event
Headers: Authorization: Bearer <token>
Body: {
  events: SyncEventRecord[]   // vedi src/sync/index.ts SyncEventRecord
}

// Pull (Railway → CLI via SSE)
GET /sync/stream
Headers: Authorization: Bearer <token>
Response: text/event-stream

event: sync
data: { id, projectId, workspaceId, aggregate, seq, type, data, timestamp, origin }

// Snapshot fetch (cold start)
GET /sync/snapshot/:aggregate/:aggregateId?projectId=...
Headers: Authorization: Bearer <token>
Response: { lastSeq, state: <JSON projection> }

// Outbox replay (catch-up)
GET /sync/outbox?projectId=...&since=<seq>
Headers: Authorization: Bearer <token>
Response: { events: SyncEventRecord[], hasMore: boolean }
```

## 5. Rischi & mitigazioni

| Rischio                                                                  | Impatto | Mitigazione                                                                                                                                                                                                                                                                                                 |
| ------------------------------------------------------------------------ | ------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Perdita eventi durante migrazione `workspace.events` JSON → `sync_event` | alto    | Script `migrate-from-workspace.ts` in transazione SQLite; smoke test su db di prova prima del rollout; rollback via backup `nikcli.db`                                                                                                                                                                      |
| Outbox unbounded se Railway offline per giorni                           | medio   | Outbox ha `attempts` + `nextAttemptAt` con exponential backoff (max 24h); alert se `outbox.size > 1000`                                                                                                                                                                                                     |
| Token CLI rubato → scrittura eventi malevoli sul server                  | alto    | Token scope `cli-sync`; rate limit 100 events/min per token; audit log di ogni evento ricevuto                                                                                                                                                                                                              |
| Sequence collision locale ↔ remoto                                       | basso   | Sequence è per `(projectId, aggregate)`. CLI e Railway sono in `projectId` diversi? NO — stesso projectID. Soluzione: `origin_seq` separato, server ri-numera in ricezione; CLI accetta il nuovo seq come canonico. Eventi locali generati offline hanno `origin_seq=null` → server ri-numera atomicamente. |
| Workspace remoto irraggiungibile durante emit                            | basso   | `Sync.emit` è sempre locale-first. Outbox gestisce retry verso remoto. Workspace remoto failure non blocca scrittura locale.                                                                                                                                                                                |
| Snapshot corrotto                                                        | medio   | `replayWithSnapshot` valida JSON.parse; se fallisce, ricomincia da seq=0 (replay completo). Snapshot è cache, non source of truth.                                                                                                                                                                          |
| V2 projector drift se cambiano schema eventi                             | basso   | V2 ha già `Stepper.stepWith` come reducer puro; projector v1 → v2 separato e testato                                                                                                                                                                                                                        |

### 6.5 Rollback strategy

Se la Fase 0 o 1 fallisce in produzione:

1. Stop CLI
2. `cp nikcli.db nikcli.db.backup-pre-sync-unify`
3. `git checkout main` (ripristina codice)
4. `bun run dev` → CLI parte con codice vecchio, DB ha già migration 0008 ma colonne nuove sono nullable/innocue → funziona
5. (Opzionale) `ALTER TABLE sync_event DROP COLUMN workspace_id` se si vuole DB pulito

La Fase 2 (remote sync) è puramente additiva: rimuovere env vars disabilita tutto. Zero rischio di rottura del CLI locale.
