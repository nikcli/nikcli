**Type**: ranked roadmap of next work across all 20 EOT specs.
**Audience**: nikcli creator + Effect/HttpApi/TUI/plugin maintainers.
**Source of truth**: `specs/ROADMAP.md`, `specs/README.md` (Evidence B01–B40), `packages/nikcli/AGENTS.md`, `specs/PRODUCT_ROADMAP.md`, plus the codebase map in this plan's appendix.
**Baseline date**: 2026-09-18 (today). Re-baseline every 90 days or after any tier exit.
**Scope**: `packages/nikcli`, `packages/tui`, `packages/llm`, `packages/plugin`, `packages/sdk`, `packages/companion`, `packages/remote`, `packages/identity`.

## Status — end of 2026-09-20

**P0 is closed.** Its exit asked for a ratified baseline artifact and a CI gate on the
comparison, and neither existed because the probe never returned: `perf-baseline.ts`
finished measuring in under a second and then hung on open handles, so no artifact could be
produced. `packages/nikcli/specs/perf-baseline.json` is the first real recording and

Eleven CI gates now exist, all in `script/ci-validate.ts`: `open-payloads`,

route coverage. Each spec's own **Addendum — 2026-09-20** carries the reasoning; this plan
stays the ranking of what is _next_.

### What the work actually found

Every spec taken to its gate produced a defect the spec had not predicted, which is the
argument for working from gates rather than from plans:

| Spec   | Found                                                                              |
| ------ | ---------------------------------------------------------------------------------- |
| EOT-01 | the baseline probe never exited, so no baseline had ever been produced             |
| EOT-02 | the bridge cannot tell a defect from an interruption; counters called both failure |
| EOT-04 | a lifetime byte budget would have evicted every session past 8 MiB                 |
| EOT-09 | `work()` silently dropped items after a nullable one; `Semaphore` was untested     |
| EOT-10 | both shipped 400s were fixed, but nothing stopped the third                        |

| EOT-18 | the requirement was pinned to a wrapper with zero registered commands              |
| EOT-19 | `/mobile/bootstrap` spawned an unbounded `npx` on the app's connect path           |

### Five corrections to this plan's own premises

1. **EOT-12's gate cannot be met by wiring `requireAccount` onto routes.** Sync, share and
   the mobile companion are account-optional by design; the one surface that needs a local
   account already has `localAccountSession`, which keeps a distinction `decide()` does not
   model. There is no route today that cannot serve an unauthenticated caller.
2. **EOT-17's "route every call through the runtime `HttpClient`" is not reachable as a
   slice.** 45 modules call `fetch`/`WebSocket`/`Bun.connect` directly. Accounting shipped
   instead; the chokepoint is a migration.
3. **EOT-18's `Lifecycle<T>` had no registered commands.** The guarantee lives in
   `cli/bootstrap.ts`'s `finally`, and the wrapper is deleted.
4. **EOT-20's "packages/tui has no tests" was the wrong package.** They live in
   `packages/nikcli/test/tui/` — 55 files, which `ROADMAP.md`'s own evidence table names.
5. **EOT-03 cannot be closed with owner-based cancellation.** A nested dialog is opened with
   `dialog.replace`, which unmounts the component that opened it, so `useAbortOnCleanup` in
   a chaining dialog is disposed as part of the flow working. Two rounds of guards were
   written and reverted; the second broke provider auth in a running TUI.

### What is left, and why it is not in this mode

The remaining specs are EOT-03, 05, 06, 07 and 19 — all TUI. `ROADMAP.md`'s evidence table
requires real OpenTUI frame assertions and PTY interaction for that surface, and states
that a passing typecheck proves none of it. Two of three TUI behaviour changes attempted
here were wrong and one reached a user. They want a session where the screen can be
watched.

EOT-11 and EOT-14's deeper slices are the L/High multi-PR migrations this roadmap already
scopes that way: a Stream topology spanning provider → SDK → SSE → TUI is not a session's
work, and starting one without finishing it is the half-migration the non-negotiables
forbid.

## 0. Non-negotiables (carry into every slice)

These come from `specs/ROADMAP.md` § Non-Negotiable Decisions 1–10 and the `AGENTS.md` rules. They outrank the spec tiers below.

1. **Preserve the runtime bridge.** No second runtime factory, second instance ALS, or per-component runtime. TUI-side Effect needs a host-provided owner + evidence it is better than `withCurrentInstance` cancellation.
2. **`Schema.TaggedError`** for new expected failures; retain `Cause`/`Exit` at internal boundaries; distinguish interruption, defect, timeout, transport failure, empty success.
3. **HttpApi stays the contract authority.** `nikcli.json` is Zod-derived via `fromZod`. Generated clients are not handwritten. No Hono, no hey-api, no parallel plugin runtime.
4. **Bounded queues need a stated overflow policy.** Faster view that drops text, permission prompts, or final outcomes is a correctness regression.
5. **CI signal is sacred.** Do not re-add the full nikcli suite to CI; use `bun run test:ci` (sharded). Never weaken a check to obtain green.
6. **Bridge protocol is one typed contract per direction.** Capability gating is part of the contract; absent capabilities are surfaced, not silently stubbed.
7. **Workspace is a typed Effect scope.** Cross-workspace reads of mutable state are typed failures; identity-based reuse dedupes; hot switch is deterministic + cancellable.
8. **Permission/sandbox/policy evaluate at every cross-boundary call.** Deny is terminal; prompt is default for undeclared ops. Headless fails closed unless pre-resolved.
9. **Observability is a first-class seam.** Spans/metrics/logs flow through `Observability.layer` with fixed-cardinality labels and redaction. OTLP opt-in; live panel default-on. Redaction is not a flag.
10. **Tests follow the three-layer architecture** (unit, integration, e2e) with deterministic fixtures, isolated DBs, PTY harnesses, barriers — never `sleep` races.
