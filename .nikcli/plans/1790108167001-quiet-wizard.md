# Plan: bring Effect-driven logic to the TUI

## Scope & framing

The user asked: _"tutto usa effect con logica?"_ — does everything use Effect for its
logic? Short answer:

- **`packages/nikcli/src/cli/cmd/tui/` (the in-nikcli bridge)** — yes. `worker.ts:7`,
  `plugin/host-local.ts:3` already use `withInstanceAsync` / `@/effect` for the only
  operations that need Effect at the entry boundary. The bridge itself is
  thin — 2 files, ~150 LOC.
- **`packages/tui` (the standalone TUI app, ~17k LOC)** — almost no. A grep
  shows exactly **one** import of `effect` in the whole package
  (`packages/tui/src/util/interaction-spec.ts:1`, only `Schema`). Everything else
  is SolidJS signals + raw Promises + a hand-rolled event bus.
- **`packages/tui/src/plugin/`** — deliberately Effect-agnostic. The host inversion
  (`packages/tui/src/plugin/host.ts:32-58`, `packages/nikcli/src/cli/cmd/tui/plugin/host-local.ts`)
  is what _lets_ `packages/tui` stay Effect-free and is the architectural centerpiece
  of the standalone package.

The plan therefore has two goals that must stay independent:

1. **Bridge** is already where it should be — confirm and lock it in.
2. **Standalone TUI** can grow Effect usage in places where it actually pays off
   (resource management, async lifecycle, errors, polling) without breaking the
   host-agnostic contract that makes the plugin runtime portable.

This is not "rewrite the TUI on Effect". Solid reactivity stays the renderer
layer. Effect is the **side-effect / async / resource layer** underneath it.

### What stays non-Effect on purpose

- `packages/tui/src/app.tsx` JSX tree and Solid reactivity — keep. Effect does
  not replace signals.
- `packages/tui/src/plugin/runtime.ts`, `api.tsx`, `slots.tsx`, `data.ts`,
  `storage.ts`, `reload.ts`, `keymap.ts` — host-agnostic by design. Migration
  of these would defeat the purpose of the inverted host.
- `packages/tui/src/ui/*` (low-level JSX primitives) — keep.

## Tiered migration plan

Each tier ships independently. Every tier ends with a green
`bun run typecheck` + the targeted test files for the touched surface.

### Tier 1 — safety (must land first)

Goal: kill the "unmount doesn't cancel" bug class by replacing polling/stream
sites with `Scope`-managed fibers.

1. **`SyncProvider` (`packages/tui/src/context/sync.tsx`)** — wrap the
   `subscribe(directory, handler)` call in `Effect.gen` with `Stream.fromEvent`-
   style construction. Finalize the inner fiber via `Effect.scoped` + a
   `Scope` finalizer that is triggered by `onCleanup` in the provider.
   _Constraint_: the `Accessor<Event[]>` returned by the context stays the same
   so the rest of the app does not change.
2. **`RemoteSyncProvider` (`context/remote-sync.tsx`)** — same treatment.
3. **`AnalyticsProvider`, `TelemetryProvider`, `KVProvider`** — replace
   `setInterval` flushes with `Effect.repeat(Schedule.spaced(...))` under
   `Effect.scoped`. Aborts on `onCleanup`.
4. **Feature-plugin polling** — `feature-plugins/loops/runner.ts`,
   `feature-plugins/background/source.ts`, `feature-plugins/devtools/store.ts`.
   Each becomes an `Effect`-shaped runner with a `Scope`; the
   Solid-facing adapter is the existing `Accessor` shape.

Verification: `bun test test/cli` (dialog/polling suites) +
`bun run typecheck`. Manually verify that dismissing a dialog while a
subscription is in flight cancels the inner fiber (no console errors).

### Tier 2 — async surface consolidation

Goal: every external I/O in the TUI is `Effect.tryPromise` or `Stream`-based,
not bare `await`.

1. **`packages/tui/src/util/rpc.ts`** — add an internal `Subject<Event, never>`
   behind the existing `emit/on` API. Keep the synchronous emit so the RPC
   hot path stays cheap.
2. **`packages/tui/src/util/clipboard.ts`, `util/sound.ts`, `util/user-api.ts`** —
   wrap in `Effect.tryPromise`; expose both a raw Promise and an Effect version
   so call sites can migrate gradually.
3. **`packages/tui/src/context/sdk.tsx`** — replace `retryTransient` +
   `createReconnectGate` with `Effect.retry(stream, { schedule: Schedule.exponential(...).union(Schedule.spaced(...)) })`.
   The reconnect status signal that the UI consumes continues to come from a
   Solid accessor.
4. **`packages/tui/src/context/server.tsx`** — boot/teardown as an `Effect.scoped`
   program. Use the same `Effect.onExit` bookkeeping as
   `packages/nikcli/src/effect/runtime.ts:88-102` (already classifies
   interrupted/failed bridges correctly).

Verification: targeted tests for `rpc`, `clipboard`, `sound`, `user-api`,
plus `bun test test/server/`.

### Tier 3 — typed errors

Goal: domain failures are `Schema.TaggedError`s, not `Error`.

1. **`packages/tui/src/util/error-format.ts`** (or a new `util/errors.ts`)
   declares the failure taxonomy: `SubscriptionDropped`, `RpcChannelClosed`,
   `UpgradeCheckFailed`, `ReconnectExhausted`. Each is a `Schema.TaggedError`.
2. **`SyncProvider`, `RemoteSyncProvider`, `AnalyticsProvider`** surface these
   to the UI by `Effect.flip` in the Solid accessor.
3. **`exit.tsx`, `upgrade.tsx`** map these tags back to user-visible messages;
   remove string-sniffing.

Verification: tests assert specific `Tag` is propagated, not just "an error
was thrown".

### Tier 4 — runtime entry shape (the last 10%)

Goal: the standalone bin and the in-nikcli worker share the same Effect-shaped
boot program.

1. **`packages/tui/bin/nikcli-tui.ts`** + **`packages/tui/src/host/standalone.ts`**
   wrap the renderer in `Effect.scoped(renderEffect)` where `renderEffect`
   produces `ExitCode`. SIGINT/SIGTERM funnel through `Effect.interrupt`.
2. **`packages/nikcli/src/cli/cmd/tui/worker.ts`** adopts the same shape
   (it already uses `Effect` via `withInstanceAsync`; the wrapper just
   becomes explicit).
3. Add a `LogRedirect`-equivalent so Effect-internal logs don't corrupt the
   TUI in standalone mode. Pattern: mirror `runtime.ts:11-36`.

Verification: spawn `bun run --cwd packages/tui start` in a tmux session,
send SIGINT, confirm clean exit with no leaked subprocesses.

## Verification matrix

Per tier, before declaring done:

1. `bun run typecheck` in `packages/nikcli` — green.
2. `bun test <test-file>` for the touched surface — quoted pass/fail counts in
   the same reply as the change. **No "tests pass" paraphrase.**
3. `bun run lint` in `packages/nikcli` — green.
4. CI guardrails unchanged: `script/ci-validate.ts`, `check:routes`,
   `generate:httpapi-clients` continue to pass.
5. For Tier 4 only: manual smoke (`bun run dev` in tmux, SIGINT, confirm clean
   shutdown; `bun run --cwd packages/tui start` same).
6. **`ci-pipeline` is non-negotiable red→green before merging.** No test
   quarantine, no `critical: false`, no reruns-as-strategy.

## Out of scope (explicitly)

- **Rewriting `app.tsx` on Effect.** Solid stays the renderer.
- **Replacing Solid signals with `Ref`/`SubscriptionRef`.** The reactivity
  model is correct as-is; Effect handles async/resource, not DOM diffing.
- **Plugin runtime migration.** `packages/tui/src/plugin/` is deliberately
  Effect-agnostic and stays that way. That decision is what makes the
  standalone ↔ in-nikcli split possible.
- **`@/effect` consumption from `packages/tui`.** `@/effect` depends on
  nikcli-only modules (`@/project/instance`, `@/server`); a standalone TUI
  cannot import it. The standalone TUI uses `effect` directly via the
  bridge patterns already in `packages/nikcli/src/effect/runtime.ts`.

## Open questions to confirm with the user before implementation

1. **Tier 1 first, or start with the easier Tier 2 wins?** Tier 1 is the
   safety work; Tier 2 has more visible cleanups but lower blast radius.
2. **Are the typed-error tags acceptable as a public surface?** New `Schema.TaggedError`s
   in `packages/tui/src/util/errors.ts` would need to be cross-stable with
   the server-side failure schemas.
3. **Tier 4 boot rewrite — is changing the standalone bin entry acceptable?**
   `packages/tui/bin/nikcli-tui.ts` and `host/standalone.ts` are public-ish
   (the bin is `nikcli-tui`).
