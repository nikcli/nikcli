# Piano: eliminazione completa di Hono da packages/nikcli

## Obiettivo e vincoli

Sostituire integralmente Hono e hono-openapi in `packages/nikcli` - server principale, API mobile, workspace server, proxy HTTP/WebSocket e tipi PTY - mantenendo invariati URL, metodi, query/header, auth, status/error body, streaming, WebSocket, OpenAPI e albero SDK pubblico.

Interpretazione concordata: la rimozione riguarda **tutto il package**, non solo `src/server/server.ts`. Non richiede in questa iniziativa l'estrazione di un nuovo `packages/server`: prima si stabilizza un unico composition root Effect/Bun nel package attuale.

## Architettura target

- `src/server/server.ts` diventa un facade framework-neutral con `fetch(request)`, `listen(options)`, `ready()`, `url()` e lifecycle; non espone piu un'app Hono.
- `src/server/httpapi/public.ts` e l'unica fonte dei contratti JSON e dei relativi handler Effect HttpApi.
- Un router raw Effect, composto prima/dopo HttpApi secondo precedenza esplicita, gestisce SSE, prompt chunked, webhook, HTML/static proxy, share redirect/data e WebSocket.
- `@effect/platform-bun/BunHttpServer` ospita HTTP e upgrade WebSocket. La versione installata supporta gia `HttpServerRequest.upgrade`/`upgradeChannel`; non serve attendere un nuovo helper upstream.
- Un middleware Effect unico applica body limit, auth/principal, logging, CORS e risoluzione workspace/instance prima del dispatch.
- OpenAPI viene generato esclusivamente da `PublicApi`; non esiste piu un generatore Hono ne una modalita duale.
- I client in-process usano `Server.fetch(request)`, la stessa pipeline usata dal listener reale.

## Principi di migrazione

- Migrare per slice indipendenti e verificabili; nessuna modifica di comportamento di dominio insieme al cambio trasporto.
- Prima rendere Effect autorevole per contratto e runtime, poi cancellare la controparte Hono.
- Ogni route deve conservare operationId, payload/query/default, status, header, error body e side effect.
- Le route raw restano dichiarate nel contratto quando SDK-visible, ma sono servite dal router raw, non forzate nell'encoder HttpApi.
- Tenere una baseline OpenAPI/SDK e wire-contract prima della prima cancellazione; ogni fase deve confrontarsi con quella baseline.
- Durante i PR intermedi il rollback e il revert del singolo PR; evitare un nuovo flag runtime dual-backend, che ricreerebbe il problema originario.

## Fase 1 - Flip definitivo OpenAPI/SDK su Effect

Questa fase precede la cancellazione dei route file Hono, per evitare che la documentazione legacy resti necessaria.

### Modifiche

- Completare gli Effect Schema canonici oggi ancora `Schema.Unknown` in `src/server/httpapi/mobile.ts` e `src/server/httpapi/contract-extra.ts`, riusando gli schema di dominio esistenti (Session, MessageV2, Provider, PTY, Project, Workspace, Loop, Routine, Config).
- Trasformare i gruppi contract-only in contratti completi; i relativi handler possono arrivare nelle fasi successive, ma non devono dipendere da describeRoute.
- Rendere `generate` Effect-only in `src/cli/cmd/generate.ts`; rimuovere `OpenApiSource`, `--httpapi`, `NIKCLI_SDK_OPENAPI` e `Server.openapi()`.
- Rendere `packages/sdk/js/script/build.ts` sempre basato su `PublicApi` e rigenerare SDK JS e client HttpApi interni.
- Conservare temporaneamente solo le normalizzazioni di `public.ts` necessarie alla compatibilita wire/SDK; annotare quali potranno essere rimosse in una futura major.

### Gate

- Comparatore OpenAPI: zero path+method mancanti, zero operationId mismatch, componenti pubblici richiesti non vuoti.
- Generazione SDK Effect produce lo stesso albero classi/metodi della baseline e il monorepo typecheck passa.
- Test minimi: `test/server/httpapi-openapi-components.test.ts`, `test/server/httpapi-public.test.ts`, test SDK/plugin type exports.

## Fase 2 - Composition root framework-neutral

### Modifiche

- Introdurre in `src/server` un request pipeline puro, riusando `HttpApiBridge.webHandler` ma rinominandolo in termini finali (per esempio `HttpApiRuntime`/`ServerRouter`).
- Portare da `src/server/server.ts` in middleware framework-neutral:
  - body limit prima dell'auth;
  - `Auth.authenticate` e principal request-scoped;
  - request logging/timing e redazione;
  - CORS/OPTIONS con la whitelist esistente;
  - directory/workspace/session resolution, remote target routing e `InstanceRef`/`WorkspaceContext`;
  - error mapping 400/404/409/500 e stack solo con `NIKCLI_DEBUG=1`.
- Convertire `src/server/middleware/body-limit.ts` da `MiddlewareHandler` a funzione `Request -> Response | undefined` o middleware Effect.
- Esporre `Server.fetch(request)` come boundary in-memory; aggiornare `src/cli/cmd/run.ts`, `src/cli/cmd/tui/worker.ts` e `src/plugin/index.ts` da `Server.App().fetch`.
- Aggiornare i test bridge a colpire `Server.fetch`, rinominandoli come test del backend unico.

### Gate

- Matrice auth completa (issuer JWT, nkm*, nku*, Basic, Tailscale, public paths, mobileAuthRequired) passa via `Server.fetch` e listener reale.
- Test body-limit, CORS, error redaction, directory header/query, session-directory lookup, workspace locale/remoto e in-process SDK passano senza Hono.
- Nessun caller runtime usa `Server.App()`.

## Fase 3 - Portare e cancellare le route JSON desktop

### Sequenza per PR

1. Top-level/app/auth/config/provider/project/file/question/permission/doctor.
2. Analytics/brain/connectors/loop/mission/MCP/experimental/workspace/TUI.
3. Session JSON incluse instructions, context, goal, monitor, background e v2.
4. Sync JSON legacy: event append, outbox, snapshot aggregate, stats, config, connect/disconnect/drain.

### Modifiche

- Implementare in `PublicHttpApi.Api` gli handler mancanti dei gruppi `ContractExtraHttpApi` e `SyncHttpApi`.
- Per ogni gruppo, usare Effect Schema come DTO autorevole e spostare eventuale logica condivisa fuori dal file Hono prima di eliminarlo.
- Eliminare progressivamente i corrispondenti file `src/server/routes/*.ts` e le registrazioni in `src/server/server.ts`.
- Sostituire `SessionProxyMiddleware` con la funzione framework-neutral gia usata dalla pipeline della fase 2.

### Gate per ogni gruppo

- Test success, validation failure, auth, not-found/conflict e side effect persistito.
- OpenAPI/SDK diff semantico zero rispetto alla baseline.
- L'inventario contratti-handler-raw resta completo.

## Fase 4 - Mobile: da contract-only a HttpApi servito

### Modifiche

- Dividere `src/server/httpapi/mobile.ts` per dominio mantenendo un unico `MobileHttpApi.Group`: auth/bootstrap, session/lifecycle, GitHub, git, workspace, teleport, memory, loop/routine e PTY.
- Estrarre dai file `src/server/routes/mobile/*.ts` funzioni/servizi di dominio, senza copiare handler Hono.
- Implementare handler Effect per tutte le operazioni mobile; mantenere esattamente wrapper, default, pagination/header, upload/chunk e cleanup.
- Aggiungere `MobileHttpApi.Group` al surface servito di `PublicHttpApi.Api`, non solo a `PublicApi`.
- Eliminare `src/server/routes/mobile/` e il mount `MobileRoutes`.

### Gate

- Tutte le operazioni mobile risultano dichiarate e servite.
- Test dedicati coprono token bootstrap, session lifecycle/prompt, git/workspace, teleport begin/chunk/finalize e PTY CRUD.
- Smoke end-to-end `nikcli mobile serve`: health, pairing token e bootstrap autenticato.
- Upload grandi rispettano il ceiling speciale e gli altri endpoint il limite standard.

## Fase 5 - Route raw HTTP: SSE, prompt, webhook, share, companion e fallback web

### Modifiche

- Comporre un `HttpRouter` raw con precedenza esplicita attorno a HttpApi:
  - `GET /event` e `GET /global/event` da `src/server/httpapi/event.ts`;
  - sync/workspace SSE con heartbeat, filtri, abort cleanup e header anti-buffering;
  - prompt chunked/async da `src/server/httpapi/prompt.ts`;
  - chatbot raw request da `src/server/httpapi/chatbot.ts`;
  - users/share redirect+JSON da handler raw dichiarati;
  - companion HTML e asset/control surface;
  - catch-all proxy a `https://app.nikcli-ai.dev` con CSP e hop-header policy invariati.
- Portare `src/server/routes/companion.ts` a modulo Response/HttpRouter senza Hono/CORS.
- Sostituire `hono/proxy` con `fetch` esplicito e copia controllata degli header.
- Eliminare le route Hono global/share/companion/chatbot/users/sync rimaste.

### Gate

- SSE verifica greeting, forma envelope corretta, heartbeat, evento inoltrato e cleanup su abort/dispose.
- Prompt verifica 200 aperto subito, JSON finale, 204 solo dopo admission e mapping 400/404/409.
- Share verifica 308 e payload pubblico; companion HTML/CSP; web fallback preserva status/body/header.
- Test di disconnect non lasciano listener GlobalBus/Bus o timer attivi.

## Fase 6 - WebSocket nativi Effect/Bun e rimozione dei tipi Hono

La versione installata espone `HttpServerRequest.upgrade` e `upgradeChannel` tramite `BunHttpServer`; usare questi primitive anziche `hono/bun`.

### Modifiche

- Definire in `src/pty/index.ts` un adapter transport-neutral (send/close/readyState o direttamente `Socket.Socket`) e rimuovere `WSContext` da `hono/ws`.
- Implementare `GET /pty/:ptyID/connect` e `GET /mobile/pty/:ptyID/connect` come raw Effect WebSocket:
  - upgrade;
  - flush buffer a chunk;
  - input testo/binary;
  - controllo resize JSON;
  - close/error cleanup.
- Riscrivere `src/server/proxy.ts` come proxy WebSocket bidirezionale su `Socket.Socket`/Bun socket, mantenendo subprotocol, binary frames, queue pre-open e close code/reason.
- Integrare l'upgrade remoto nel middleware workspace senza app Hono interna `/__workspace_ws`.
- Aggiornare `src/cli/cmd/tui/worker.ts` a tipi Bun/Effect, non `BunWebSocketData` Hono.

### Gate

- Test WebSocket reali contro porta effimera: connect PTY, input/output, resize, buffer replay, close e missing PTY.
- Test proxy remoto: text/binary, subprotocol, queue, close/error propagation.
- `rg 'hono/(bun|ws)' packages/nikcli/src packages/nikcli/test` non trova match.

## Fase 8 - Listener unico e cancellazione finale

### Modifiche

- Fare di `src/server/server.ts` il facade finale sul layer `BunHttpServer`, incorporando:
  - port 4096/ephemeral fallback;
  - hostname, maxRequestBodySize e idleTimeout;
  - graceful drain con force-close bounded;
  - mDNS, analytics share e workspace syncing lifecycle;
  - `url()`, `ready()` e shape compatibile del server restituito a serve/mobile/TUI.
- Eliminare `src/server/httpapi/bridge.ts` come bridge/allowlist; tenere solo eventuali primitive rinominate del router finale.
- Eliminare `src/server/backend.ts`, il flag `NIKCLI_EXPERIMENTAL_HTTPAPI`, fallback tests e PoC `backend-runtime.ts` dopo che il backend unico e operativo.
- Eliminare `src/server/routes/`, i test Hono-specifici e gli script basati su `App().routes`.
- Rimuovere da `packages/nikcli/package.json` `hono`, `hono-openapi`, `@hono/standard-validator` e `@hono/zod-validator`; aggiornare il lockfile con Bun.
- Aggiornare specs e AGENTS per dichiarare Effect HttpApi/raw HttpRouter + BunHttpServer come unica architettura.

### Gate finale

1. Assenza statica:
   - `rg -n 'from ["'"']hono|hono-openapi|@hono/' packages/nikcli/src packages/nikcli/test packages/nikcli/script packages/nikcli/package.json` -> nessun match.
   - `bun pm ls | rg '(^|\s)(hono|hono-openapi|@hono/)'` non mostra dipendenze dirette di `nikcli-ai`.
2. Contratti:
   - inventario contract-handler-raw completo;
   - OpenAPI Effect contiene tutti i path/metodi/operationId baseline;
   - SDK rigenerato senza namespace/metodi mancanti e plugin typecheck verde.
3. Runtime:
   - test server completi, auth, body/CORS, session/prompt, mobile, sync/SSE, workspace e WebSocket reali;
   - smoke `nikcli serve --stdio`, `nikcli run`, TUI RPC direct fetch, `nikcli mobile serve` e `nikcli workspace-serve`.
4. Qualita/package:
   - `bun run typecheck`;
   - `bun run test`;
   - `bun run test:integration`;
   - `bun run test:e2e`;
   - `bun run build --single --skip-install` o equivalente package build;
   - rigenerazione SDK `./packages/sdk/js/script/build.ts` e typecheck monorepo.

## Strategia PR raccomandata

1. Baseline/inventario e test di parity.
2. Effect OpenAPI/SDK default e schema domain completi.
3. Request pipeline + `Server.fetch` framework-neutral.
4. Route JSON desktop, in piu PR per gruppi.
5. Mobile, diviso per dominio.
6. Raw HTTP/SSE/prompt/share/companion/web fallback.
7. PTY + remote workspace WebSocket.
8. Workspace server.
9. Listener/lifecycle definitivo, cancellazione Hono e dipendenze.

Ogni PR deve essere autonomamente verde e non lasciare una nuova seconda architettura permanente. La cancellazione delle dipendenze avviene solo nell'ultimo PR, dopo che `rg`, inventory, SDK parity e smoke runtime provano che nessun path dipende piu da Hono.
